Шаг ноль: что такое агент

Обычный чат отвечает один раз. Агент получает цель и сам решает, что делать дальше: читает файлы, запускает команды, смотрит на результат и пробует снова, пока задача не будет готова.

Вся идея помещается в несколько строк:

цель = "разобрать отчёт и прислать итоги"

пока задача не готова:
    ответ = модель(цель + всё, что уже произошло)   # думает
    если ответ просит инструмент:
        результат = выполнить(инструмент)           # действует
        запомнить(результат)                        # смотрит, что вышло
    иначе:
        вернуть ответ

Модель, инструменты и цикл. Всё остальное в этой программе нужно, чтобы такой цикл работал надёжно, не ошибался молча и не стоил лишних денег.

  1. Шаг 1

    Как думает модель

    Прежде чем строить агентов, нужно понимать, на что способна модель и где она ошибается уверенным тоном.

    • токены, контекст и почему модель «забывает»
    • что такое галлюцинации и как их проверять
    • какие задачи стоит поручать ИИ, а какие нет
    • AcademyClaude 101
    • AcademyAI capabilities and limitations
    • AcademyAI Fluency: Framework and foundations

    Практика: дайте Claude задачу из своей работы и найдите в ответе минимум одну ошибку или неподтверждённое утверждение.

  2. Шаг 2

    Как ставить задачи

    Агент выполняет то, что вы описали, а не то, что имели в виду. Хорошая постановка задачи экономит часы.

    • роль, контекст, ограничения и формат результата
    • примеры вместо длинных объяснений
    • системный промпт и как его улучшать
    • ЧитатьPrompt engineering: обзор
    • ЧитатьОткрытые курсы Anthropic на GitHub

    Практика: напишите инструкцию для одной повторяющейся задачи и улучшайте её, пока три запуска подряд не дадут нужный результат.

  3. Шаг 3

    Первый настоящий агент: Claude Code

    Лучший способ понять агентов: поработать с готовым. Claude Code читает проект, меняет файлы, запускает команды и проверяет себя.

    • установка и первый запуск
    • разрешения: что агенту можно делать без вопроса
    • CLAUDE.md как постоянная память о проекте
    • режим планирования и проверка результата
    • AcademyClaude Code 101
    • AcademyClaude Code in Action
    • ЧитатьДокументация Claude Code

    Практика: решите с Claude Code реальную задачу: отчёт из таблицы, небольшой сайт или разбор папки с файлами.

  4. Шаг 4

    Навыки и подагенты

    Когда одна и та же работа повторяется, её стоит оформить один раз. Большие задачи лучше делить между отдельными подагентами.

    • Skills: упакованные инструкции под конкретную работу
    • подагенты: отдельный контекст для отдельной задачи
    • когда разделение помогает, а когда только мешает
    • AcademyIntroduction to agent skills
    • AcademyIntroduction to subagents

    Практика: превратите инструкцию из шага 2 в Skill и запустите её в новой сессии.

  5. Шаг 5

    Инструменты и MCP

    Агент полезен настолько, насколько полезны его инструменты. MCP это общий способ подключить к нему почту, базы данных, таблицы и внутренние системы.

    • как модель вызывает инструмент
    • MCP: серверы, инструменты, ресурсы и промпты
    • как описать инструмент так, чтобы агент не ошибался
    • AcademyIntroduction to Model Context Protocol
    • AcademyMCP: Advanced topics
    • ЧитатьWriting tools for agents
    • ЧитатьСпецификация и примеры MCP

    Практика: напишите с помощью Claude Code свой MCP-сервер с одним инструментом и подключите его к агенту.

  6. Шаг 6

    Свой агент в коде

    С этого шага нужен код. Основы программирования можно подтягивать вместе с Claude Code: цикл из начала страницы теперь пишем сами.

    • запросы к Claude API и ключи
    • вызов инструментов и цикл агента
    • Agent SDK: готовый цикл вместо самописного
    • стоимость запросов и кэширование промптов
    • AcademyClaude Platform 101
    • AcademyBuilding with the Claude API
    • ЧитатьAgent SDK: обзор

    Практика: соберите агента примерно на 50 строк с двумя инструментами, а затем перепишите его на Agent SDK.

  7. Шаг 7

    Архитектура и контекст

    Не каждой задаче нужен агент: часто надёжнее простая цепочка шагов. Здесь учимся выбирать самое простое решение, которое работает.

    • цепочки, маршрутизация и параллельная работа
    • оркестратор с исполнителями, проверяющий и исполнитель
    • что держать в контексте, а что выносить в файлы
    • как распределить работу между людьми и агентами
    • ЧитатьBuilding effective agents
    • ЧитатьEffective context engineering
    • AcademyBuilding effective human-agent teams

    Практика: нарисуйте схему своего агента и уберите из неё всё, без чего он справится.

  8. Шаг 8

    Качество и безопасность

    Агент, который работает на одном примере, ещё не готов. Перед запуском нужно измерить качество и ограничить, что он может сломать.

    • оценка: набор задач с понятным критерием успеха
    • инъекции промптов через письма, сайты и документы
    • минимальные права и подтверждение человеком опасных действий
    • логи, лимиты расходов и остановка зацикливания
    • AcademyIntroduction to evals
    • ЧитатьDemystifying evals for AI agents

    Практика: напишите 10 проверочных задач для своего агента и прогоняйте их после каждого изменения.
